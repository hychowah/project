    Relay — Personal AI Agent Workspace

    A personal AI agent workspace that connects my own apps through one conversation. Any app can give the agent an interface through a small HTTP protocol.

    Project focus

    Overview

    Personal project · Nov 2026 – Present

    Prototype in daily use.

    Relay is an AI agent workspace I built to work across my own tools. Each app opens as a tab, and one conversation stays beside them. When a question needs an app, the agent calls that app’s operations, answers with references to its source, and can show the result on the app’s own screen.

    Any app can join without changes to Relay, and joining gives the agent an interface to it. My URDF robot viewer, for example, became something the agent can use to check a robot model and test joint motions, which is how I tested the gesture motions on the DIY dexterous hand page.

    Agent Workspace

    The Relay service runs on Node 24 with SQLite and an agent runtime that can use Claude, OpenAI or DeepSeek models. It keeps conversations, memory and model keys in one place, never in the clients or apps. The main client is a Flutter app for macOS, with tabs, split views and a built-in browser. A React page provides the same chat and apps on other computers.

    • Isolation: each app runs on its own origin in a sandboxed frame. Shared folders are read-only, with hidden files such as .env kept out of reach.
    • The user takes the last step: the agent can fill in a web form for review, but submitting it is left to me.
    • Network safety: the service answers only its own address, so other websites cannot reach it through a renamed domain (DNS rebinding).
    • Persistence: tabs, split views and the conversation return after a restart, and other devices can open the same tabs.

    Apps As Agent Interfaces

    An app keeps its own screens and technology, and Relay holds no code for any particular app. To give the agent an interface, the app serves a small HTTP protocol:

    • Manifest: the app’s name, what it is for and how to use it.
    • Operations: named calls the agent loads only when a question needs that app, so other apps stay out of the model’s context. The agent sees only what the operations return.
    • Views: an operation can return a view, such as a part to highlight, which the app draws on its own screen inside Relay.

    The robot viewer shows how this works. It is a self-hosted three.js app for URDF and xacro models, and through Relay it offers operations to inspect a robot, edit its files (guarded so an edit cannot overwrite someone else’s change), play a keyframed joint motion and capture a frame of it. With these, an agent wrote the hand’s gesture motions, checked the captured poses for finger interference and refined the keyframes while I watched the same viewer in a tab.
